# 1. PURPOSE

The purpose of `positioning.ts` is to answer:

> **"How are market participants positioned, how is that positioning changing, and does positioning support or conflict with the current price movement?"**

The primary inputs are:

* Open Interest (OI)
* Long/Short ratio (LS Ratio)
* price movement

The module should identify:

* OI level
* OI change
* OI trend
* Long/Short ratio
* Long/Short ratio change
* positioning bias
* crowding
* positioning/price relationships
* divergence
* potential trapped positioning
* positioning confirmation/conflict
* timeframe alignment
* directional interpretation
* explainable reasons

This is **not a liquidation engine**.

This is **not a trade signal generator**.

This is **not a prediction model**.

It should describe the positioning environment and its relationship with price.

---

# 2. IMPORTANT ARCHITECTURE

The architecture is approximately:

```text
CandleInfo
    │
    ├── candleStructure.ts
    ├── anchorDecisionEngine.ts
    ├── priceAction.ts
    ├── volumeState.ts
    │
    ▼
positioning.ts
```

The positioning module should consume existing price/candle information where useful.

Do NOT duplicate calculations already provided by other modules.

For example, do not recreate:

* candle structure
* price-action events
* volume analysis

Use existing results if available.

---

# 3. CORE PRINCIPLE

Positioning should NOT be interpreted independently.

For example:

```text
OI ↑
```

does NOT automatically mean:

```text
BULLISH
```

And:

```text
OI ↓
```

does NOT automatically mean:

```text
BEARISH
```

OI tells us about changes in open positions.

The meaning depends heavily on:

```text
price movement
+
OI change
+
Long/Short positioning
+
timeframe context
```

Likewise:

```text
LS Ratio > 1
```

does not automatically mean price will rise.

It means the measured long/short positioning is relatively long-biased.

The module must preserve this distinction.

---

# 4. REQUIRED TIMEFRAMES

Positioning should support:

```text
15m
1h
4h
```

and optionally:

```text
1d
```

The most important architecture is:

```text
4H → higher-timeframe positioning context
1H → setup positioning
15M → immediate positioning
```

Do NOT simply average these timeframes.

Each timeframe should be analyzed independently first.

Then derive alignment/divergence.

# 6. OI CHANGE MUST BE CAUSAL

At candle/index `N`, only use OI information available through `N`.

Never use:

```text
future OI
future price
future positioning
```

No look-ahead.

The module must work in realtime and historical backtesting.

---

# 7. OI TREND

Do not only compare:

```text
current OI
vs
previous OI
```

when enough historical data exists.

Also determine whether OI is:

```text
rising
falling
stable
```

over a configurable rolling window.

For example:

```text
Candle 100 → OI 100
Candle 101 → OI 103
Candle 102 → OI 106
Candle 103 → OI 110
```

This is more meaningful than a single OI increase.

Use configurable windows.

Do not use hardcoded absolute OI values.

# 8. LONG / SHORT RATIO

```ts
LSRatioState
```

```ts
interface LSRatioState {

  reasons: string[]
```

Adapt if necessary.

```text
LS ratio
```

describes positioning bias.

# 9. INTERPRETING LS RATIO

Use a configurable neutral range rather than simplistic:

```text
> 1 = bullish
< 1 = bearish
```

For example, depending on the data convention:

```text
LS = 1.00
```

may be considered relatively balanced.

But:

```text
LS = 1.45
```

could indicate significant long-side crowding.

Likewise:

```text
LS = 0.70
```

could indicate significant short-side crowding.

Use configurable thresholds such as:

```ts
LS_LONG_CROWDING_THRESHOLD
LS_SHORT_CROWDING_THRESHOLD
LS_BALANCED_RANGE
```

Do not hardcode these throughout the implementation.

# 10. MOST IMPORTANT PART: PRICE + OI

The module should classify common price/OI relationships.

Use a framework similar to:

```text
                    OI INCREASES
                 │
                 │
Price UP         │   New longs / bullish participation
                 │
Price DOWN       │   New shorts / bearish participation
                 │
─────────────────┼──────────────────
                 │
Price UP         │   Short covering
                 │
Price DOWN       │   Long liquidation / long closing
                 │
                    OI DECREASES
```

But do NOT blindly label these.

Use:

* magnitude of price change
* magnitude of OI change
* direction
* LS ratio
* recent positioning context

to determine the most likely positioning interpretation.

---

# 11. PRICE UP + OI UP

This generally indicates:

> New positions are entering while price rises.

This can be consistent with:

```text
NEW_LONGS
```

especially when LS positioning is also becoming more long-biased.

Example:

```text
Price +1.2%
OI +4.5%
LS 1.35
```

Possible interpretation:

```text
BULLISH_POSITIONING
```

Reasons:

```text
"Price increased 1.2%"
"Open interest increased 4.5%"
"Long-side positioning is elevated at 1.35"
"Rising price is accompanied by increasing open interest"
```

Do NOT call it guaranteed new longs.

Use wording such as:

> "Consistent with long positioning entering."

---

# 12. PRICE DOWN + OI UP

This generally indicates:

> New positions are entering while price declines.

This can be consistent with:

```text
NEW_SHORTS
```

especially when LS positioning is becoming more short-biased.

Example:

```text
Price -1.1%
OI +5.2%
LS 0.72
```

Possible interpretation:

```text
BEARISH_POSITIONING
```

Again, phrase the reasoning probabilistically:

> "Consistent with short positioning entering."

Do not claim certainty.

---

# 13. PRICE UP + OI DOWN

This often indicates:

> Positions are being closed while price rises.

This can be consistent with:

```text
SHORT_COVERING
```

especially when the existing positioning was short-heavy.

Example:

```text
Price +2.0%
OI -6.0%
LS 0.68 → 0.82
```

Potential interpretation:

```text
SHORT_COVERING
```

This can produce strong price movement without equivalent new participation.

That distinction is important.

---

# 14. PRICE DOWN + OI DOWN

This can be consistent with:

```text
LONG_CLOSING
```

or:

```text
LONG_LIQUIDATION
```

depending on the surrounding context.

Example:

```text
Price -1.8%
OI -7.2%
LS 1.42 → 1.18
```

Possible interpretation:

```text
LONG_UNWINDING
```

Do NOT automatically call this liquidation.

Actual liquidation requires stronger evidence.

Use wording such as:

> "Consistent with long positioning being reduced."

---

# 15. DO NOT OVERCLAIM POSITIONING CAUSE

This is critical.

OI and LS data generally cannot prove exactly which market participants caused a move.

Therefore avoid statements like:

```text
"100% new longs entered."
```

Instead:

```text
"Price and OI increased together, consistent with new long positioning."
```

Or:

```text
"Price increased while OI declined, consistent with short covering."
```

This keeps the analysis statistically/structurally honest.

# 16. POSITIONING REGIMES

Create a useful positioning classification.

For example:

```ts
export type PositioningRegime =
  | 'LONG_BUILDUP'
  | 'SHORT_BUILDUP'
  | 'SHORT_COVERING'
  | 'LONG_UNWINDING'
  | 'NEUTRAL'
```

Potential mapping:

```text

Price ↓ + OI ↑ → SHORT_BUILDUP
Price ↑ + OI ↓ → SHORT_COVERING
Price ↓ + OI ↓ → LONG_UNWINDING
```

But use LS ratio and magnitude as contextual confirmation.

Do not force a regime when the evidence is weak.

---

# 17. CROWDING

Positioning crowding is important.

Detect when:

```text
LS ratio becomes significantly skewed
```

and ideally when that skew is persistent or increasing.

For example:

```text
4H LS = 1.10
1H LS = 1.25
15M LS = 1.48
```

This may indicate:

> Increasing local long crowding.

Likewise:

```text
4H LS = 0.92
1H LS = 0.78
15M LS = 0.63
```

may indicate:

> Increasing local short crowding.

Crowding is NOT itself a LONG or SHORT signal.

It is a risk/context condition.

---

# 18. TIMEFRAME POSITIONING STRUCTURE

Analyze the timeframes independently.

For example:

```text
4H:
OI ↑
LS 0.78

1H:
OI ↑
LS 0.84

15M:
OI ↑↑
LS 1.42
```

Do not average this into:

```text
LS = 1.01
```

That would destroy useful information.

Instead identify:

```text
HTF positioning → short-biased
Local positioning → long-crowded
```

This is potentially important because local longs may be trading against higher-timeframe positioning.

For example:


or another robust method.

Avoid arbitrary absolute OI thresholds.





# 27. CROWDING SHOULD NOT BE TREATED AS DIRECTION

This is very important.

Example:

```text
LS = 1.50
```

means long-heavy positioning.

It does NOT mean:

```text
LONG SCORE = 100
```

In fact, extreme long crowding can represent:

> increased downside vulnerability if price fails.

Likewise extreme short crowding can create upside vulnerability.

Therefore expose crowding separately from directional confirmation.

---

# 28. TRAPPED POSITIONING

Identify potential trapped positioning when appropriate.

Example:

```text
Price breaks upward
+
OI rises strongly
+
LS becomes heavily long
+
price subsequently fails/rejects
```

At the moment of the rejection, the system may identify:

> Potentially trapped longs.

Likewise:

```text
Price breaks downward
+
OI rises
+
LS becomes heavily short
+
price reclaims upward
```

may indicate:

> Potentially trapped shorts.

Do NOT use future candles to identify this.

Only identify it when the current candle itself provides the evidence.

Use wording such as:

```text
"Positioning is potentially trapped"
```

rather than asserting certainty.

---

# 29. LIQUIDATION VS UNWINDING

Do not automatically equate:

```text
OI ↓
```

with liquidation.

OI reduction may result from:

* voluntary closing
* short covering
* long unwinding
* liquidation
* other position reduction

Without liquidation data, do not claim actual liquidation.

Use:

```text
LONG_UNWINDING
SHORT_COVERING
POSITION_REDUCTION
```

where appropriate.

If actual liquidation information exists in the existing architecture, it may be consumed, but do not implement a liquidation data source here.

