# 1. PURPOSE

The sole purpose of `anchorDecisionEngine.ts` is to determine:

> **Which candle should be used as the anchor candle for each analytical system?**

I do NOT want this module to calculate Heatmap, AVWAP, or FRVP.

I do NOT want this module to calculate:

* liquidity zones
* VWAP
* anchored VWAP values
* volume profile
* POC
* VAH
* VAL
* trading signals
* LONG/SHORT predictions
* final scores

The engine is simply an **anchor locator**.

Its fundamental job is:

```text
Given candles[0...N]

        ↓

Find meaningful anchor candidates

        ↓

Evaluate them independently for:
    • Heatmap
    • AVWAP
    • FRVP

        ↓

Select the appropriate candle for each system

        ↓

Return the candle index
```

For example:

```text
Heatmap → candle 493
AVWAP   → candle 512
FRVP    → candle 497
```

The downstream Heatmap/AVWAP/FRVP modules will later receive those candle indices and perform their own calculations.

The most important property of the result is:

```ts
candleIndex: number
```

I primarily need to know:

# 3. MULTIPLE ANCHORS ON THE SAME CANDLE ARE VALID

This is extremely important.

**Do NOT assume that one candle can only have one anchor.**

A single candle may be the correct anchor for multiple analytical systems.

For example:

```text
Candle 493
├── Heatmap → CONSOLIDATION_START
├── FRVP    → RANGE_START
└── AVWAP   → IMPULSE_ORIGIN
```

This is completely valid.

Another example:

```text
Candle 512
├── Heatmap → LIQUIDITY_REGIME_CHANGE
└── AVWAP   → LIQUIDITY_SWEEP
```

Therefore:

> **Each analytical system must select its anchor independently.**

Do NOT create a global rule such as:

```text
one candle = one anchor
```

Instead:

```text
Heatmap → independently determine best anchor candle
AVWAP   → independently determine best anchor candle
FRVP    → independently determine best anchor candle
```

The same `candleIndex` may appear in multiple results.

The same candle may also have a different `type` for each analytical system.

For example:

```ts
{
  heatmap: {
    candleIndex: 493,
    type: 'CONSOLIDATION_START',
    ...
  },

  avwap: {
    candleIndex: 493,
    type: 'IMPULSE_ORIGIN',
    ...
  },

  frvp: {
    candleIndex: 493,
    type: 'RANGE_START',
    ...
  }
}
```

This is preferred.

The goal is NOT to find one globally "best" anchor.

The goal is:

> **Find the best anchor candle for each analytical system.**

* meaningful structure transition
* impulse origin
* liquidity regime change
* session start when appropriate




The engine should identify the **origin of the regime**.

Do not simply select the candle with the largest liquidity-related activity.

At candle `N`, it may only use:


Use sensible stability/hysteresis logic if the architecture requires state.
